1. System map — the four layers

This repo is two things at once: a .NET 8 AI gateway (src/lab-observability-api/) and a self-documenting process for building it day by day, encoded almost entirely as Claude Code configuration. The process layer has four tiers, each one consuming the layer below it.

1. Instructions

.claude/instructions/
The master script. Defines STEP 0–12 and what model/surface runs each one.

2. Commands & Skills

.claude/commands/
.claude/skills/
The verbs the instructions invoke. A command is a one-shot recipe; a skill is reusable know-how a command or you can pull in.

3. Standards

docs/standards/
The knowledge commands/skills read from and write decisions into. Naming rules, error taxonomy, cert mapping, etc.

4. Artifacts

docs/notes/, docs/adr/, src/
What actually gets produced: code, ADRs, day notes, the changelog.

Two enforcement mechanisms run underneath all four layers:

Hooks

.claude/settings.json
Fire automatically on every Write/Edit — no command has to remember to call them.

Scripts

scripts/*.js
Stateless checkers (md-backtick-wrap.js, symbol-drift-check.js) invoked by hooks, commands, and STEP 8 of the workflow.

2.4 Instructions — the master workflow

FileWhat's actually inside
daily-workflow.mdThe one-page overview: the STEP 0–12 table (surface/model/what happens per step), four governing rules (chat only for STEP 2/4/5/11; Sonnet everywhere except STEP 5/11; close each chat step the moment it ends; STEP 0 is never optional), the "auto-print handoff" mechanic (each Claude Code step prints the next step's pre-filled prompt so you never hunt for it), an "if you get stuck" troubleshooting list, the command reference table (all 7 real commands + the 3 prompt-based gates), and a token-discipline reminder.

Also contains the exact STEP 8 pillars-audit prompt and the exact STEP 12 close-audit prompt referenced in §5 and §7 of this document.

You read the overview to orient; you paste from the steps file to actually run a step.

.markdownlint.json (repo root)The lint rule overrides for every .md file in the repo: everything on by default, with 6 rules explicitly disabled — MD013 (line length), MD024 (duplicate headings), MD025 (single top-level heading), MD036 (emphasis used instead of a heading), MD041 (first line must be a top-level heading), and MD060.
.gitignore / .gitattributes.gitignore excludes build output (bin/, obj/, publish/), machine-local hook output (.claude/cert-tags-today.txt), and stray test artifacts. .gitattributes forces consistent CRLF line endings on Windows so git stops reporting line-ending-only diffs on every edit.

8. Findings from this audit

Fixed — severe: a buggy md-backtick-wrap.js replace callback (before its fix in commit 1e33390) had collapsed full paths/commands down to single letters inside backticks across 50 files, 80 occurrences — /health → `h`, /cert-update → `c`, etc. Recovered every instance from git history and added a permanent guard so this class of corruption can't recur silently.
Fixed: 6 source files (ApiError.cs, TestController.cs, HttpContextExtensions.cs, CorrelationIdMiddleware.cs, ClaudeProviderException.cs, the main .csproj) existed with zero changelog provenance — every src/ file now traces to a Day NNN.
Open, not a bug: .claude/hooks/cert-tag.json generates tags nothing consumes (see §2.3). Worth deciding whether to wire it into /cert-update or remove it.
Open, accepted debt: ADR-001/002/003 predate the "Alternatives Considered" convention. Not fixed — adding that section retroactively to an Accepted ADR isn't a "factual correction" under this repo's own ADR-immutability rule.

9. Expected results

When every layer is working together correctly, a closed day means: the code builds and tests pass; the ADR (if any) has all required headings and no open placeholders; every touched file has a changelog.md row under that day's section; every cert domain marked Primary/Secondary in the day's summary has a corresponding day-mapping row; symbol-drift-check.js and markdownlint both report zero findings; the deploy succeeded and was verified against the live App Service; and the posture-check honestly names what's still YELLOW. /repo-audit is the single command that verifies all of this at once — a clean run is the actual definition of "Day N is done."
